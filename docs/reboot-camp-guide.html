なぜ変容が求められるのか ① アジャイルコーチ・SM

セレモニーの運営から、
不確実性の伴走へ

AIが定例の要約・レポート・進捗の可視化を肩代わりする。「儀式の運営が上手い」だけでは価値を示しにくい——プロセスの機械的な部分から先にAIに置き換わる。開発が速くなるほど、勝負は「誰のために、どんな切実な課題を解くために作るのか」という問いに誠実に向き合うことへ移る。

役割役割の変容

プロセスの番人 → チームが仮説検証・学習を回すのを引き出す触媒へ。空気を読み、上辺だけのコミットを見抜き、事業成果と現場をつなぐ——AIに代替されにくい人間的判断。

行動行動の変容

顧客やチームに説く経験駆動を、まず自分のキャリアと支援で実践する。予測でなく、小さな実験で確かめる。

なぜ変容が求められるのか ② エンジニア

コードを書く人から、
AIと課題を切り拓く人へ

AIコーディング支援がルーティンな実装を吸収する。「書く」より、設計・レビュー・判断に時間の重心が移る。技術スキルの半減期は約2.5年——同じスキルのまま走り続けられない。よく定義された孤立タスクほど、先にAIが担う。

役割役割の変容 — 両側へ

①先進的で込み入った技術へダイブ：AIがまだ苦手な領域を切り拓く。②顧客・ドメインの理解へ：誰のどんな切実な課題を解くかを枠づける。実装者から、設計・判断・舵取りへ。

行動行動の変容

小さく試して学び、絶えず作り直す。ドメイン知識 × ツール習熟を掛け合わせ、AIの出力を導き検証する側に立つ。

アンチパターン03

AI壁打ち沼

「AI対話で前進した気になる」罠。AIといくら壁打ちしても、外界には一度も触れていない。言語化は進み、もっともらしい計画は量産できるのに、確信の根拠はゼロのまま。——AIが当たり前になった今、最も嵌まりやすい落とし穴。

この研修の目的04

壁打ちに、とどまらない。

仮説を立て、行動し、学びを得て、判断する—— この一巡を繰り返し、記録し、自分だけのインサイトを得る。

キャリアの目的は、頭の中でなく、この繰り返しの中で立ち上がる。

全体の流れ05

記録して回す、キャリアの学習ループ

壁打ちAIと言語化 → 仮説P 目的仮説 → 行動ACT 行動計画 → 学びLEARN 学習 → 判断DEC 意思決定 ↻ インサイト記録から見える

貫く原則＝証拠の非対称性。 壁打ちだけでは確信は上がらない。外界に触れた行動（試行・他者反応）で、初めて上がる。

ツールの特徴 ①06

記録が主役 — 対話で終わらせず、型で残す

思考の各要素を型のついたレコードとして残すから、後から「この確信はどの行動の、どの反応に基づくか」を辿れる。

P目的仮説

立ち上げつつある目的。「確信度」を持つ唯一のレコード。

ACT行動計画

やる前に立てる試行の計画（方法・成功基準・許容損失）。結果は書かない。

LEARN学習

やった後の学び（事実・解釈・驚き）。確信度を動かす根拠はここ。

DEC意思決定

ピボット・棚上げ・巻き戻しなど岐路の判断を残す。

＊ほかに C（手中の鳥＝手の内の資源）。壁打ちや内省は LEARN の回顧型（type: self-reflection）として残す（＝独立レコードは持たない）。ACTとLEARNをあえて分ける＝成功基準を後からこっそり書き換える後知恵バイアスを防ぐ。

ツールの特徴 ②・核心07

確信度は、壁打ちでは上がらない

外界に触れた行動があったときだけ上がる。しかもツールが機械的にそれを守る——壁打ちだけで確信度を盛ろうとすると lint がエラーで弾く。「言うだけ」でない。

壁打ち
AIとの対話のみ — 上がらない
試行
自分で小さくやってみた
他者反応
第三者が実際に動いた
継続
繰り返し起きている

証拠の階梯（弱→強）。壁打ちログは、目的文を磨く・確信度を下げるのには自由に使える。上げるときだけ外界の証拠を要求する。

ツールの特徴 ③

不確実な領域では、
目的すら“事後的に”立ち現れる

不確実性が高いほど、目的は先に決めきれない。手段だけでなく、目的そのものを探索する。手の内にあるものから小さく動き、外界の反応を受けて、目的は事後的に立ち現れてくる。

だから、はじめの確信度は低くていい（1〜2）。そこで確信を高めようと焦らない。記録が溜まると、系譜・試行ボードに「確信が 1→5→7 と育った軌跡」と「次に確かめるべき目的」が見えてくる——それがインサイトだ。

二つの温度。 「頭の確信（目的の硬さ）」と「当事者性（腰の入り）」は別物。
偽の収束に注意。 確信は高いのに腰が入っていない状態を、いちばん警戒する。

ツールの特徴 ④09

規律が、誠実な学習を守る

  • ◆生データ（sources）は書き換えない。 観測した事実を後から都合よく上書きしない。
  • ◆成功基準は後から変えない。 「うまくいったことにする」を構造で禁じる。
  • ◆確信度の増減は、必ず外界の出来事に紐づく。 「なんとなく自信がついた」を許さない。
  • ◆ビュー（一覧・系譜）は自動生成。 見栄えを手で飾れない＝真実源はレコード。

だから記録は、自分に都合よく作った物語でなく、学習の正直な鏡になる。

ハンズオン手順 6 · ペア演習16

相互インタビュー（The Mom Test）

The Mom Test＝相手が気を遣っても“嘘”が出ない聞き方。意見でなく過去の行動を聞き、自分の仮説は売り込まない。ペアで相手の目的を聞き合う（次の1on1のリハーサルにもなる）。

問い方を変える

✗ 悪い問い　「この目的、応援したい？」 → お世辞・励ましが出る

○ 良い問い　「最近その分野で“実際に動いた”のは？ いつ・何を？」 → 過去の事実が出る

  • ・自分の仮説を先に見せない。見せると相手は気を遣って肯定する。まず相手の経験を引き出す。

相手の反応を仕分ける

壁打ち
意見・お世辞・「いいね」— 証拠にならない
試行
自分で小さく試して起きたこと
他者反応
相手が時間・紹介・次の約束などコストを払った
継続
一度きりでなく繰り返し起きている

確信度を上げてよいのは〈他者反応〉から。「面白いね」では上げない。
