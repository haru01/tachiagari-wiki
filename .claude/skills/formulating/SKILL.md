# /formulating — 種を反証可能な目的仮説に精錬し、手中の鳥に接地する

`/surfacing` で出た種や曖昧な思いつきを、確信度とステータスを持つ**反証可能な目的仮説**に変え、**手中の鳥（制約C）に接地する**。**一度に1問ずつ**深掘りする。エフェクチュエーション①手中の鳥（いま手の内にある手段から立ち上げる）をこの精錬手順に織り込む。

> **共通規約**（案件解決・ID/接頭辞・リンク記法と `../` 深さ・.gitkeep・承認規律）は [CLAUDE.md「スキル共通規約」](../../../CLAUDE.md)、エフェクチュエーション理論は [playbooks/effectuation.md](../../../playbooks/effectuation.md) が正典。以下は本スキル固有の手順。

## 手順

1. **現在案件を読む**（→ 共通規約1）。[playbooks/formation.md](../../../playbooks/formation.md) の「問いかけバンク B（反証可能化）」を読む。`wiki/index.md` で対象の種／既存 P、`wiki/constraints/` の既存 C を把握する。

2. **手中の鳥を数える（①・接地の材料）** — `AskUserQuestion` で Effectuation の三分法に沿って、いま実際に使える所与の資源を具体で棚卸しする（抽象的な理念でなく手段として）:
   - **自分は誰か**（type: 自分は誰か）— アイデンティティ・価値観・譲れない好み・向き不向き。
   - **何を知っているか**（type: 何を知っているか）— 知識・経験・専門・過去にやり切ったこと。
   - **誰を知っているか**（type: 誰を知っているか）— 頼れる人・つながり・コミュニティ。
   - 意味のある単位ごとに `wiki/constraints/` の既存最大+1で `C-NNN` を採番し `templates/constraint.md` で起票する（`id` はファイル名と同じ接頭辞つき、`type` は上記3種、本文に「これがどう目的の出発点になるか」）。既にある C は再利用する。制約は確信度を持たない。

3. **1問ずつ深掘りする** — `AskUserQuestion` で問いかけバンク B を**1問ずつ**。特に「何が起きたら“やっぱり違った”と分かるか（反証条件）」「目的を果たしている具体的な一日」「いま数えた手中の鳥（[[C-NNN]]）のどれから立ち上がるか」を詰める。回答が曖昧なら反証可能になるまでさらに1問。
   - ※ 当事者性温度（腰の入り方）での**出題分岐はフェーズ2**。フェーズ1では観測手がかりとして自由記述で拾うにとどめ、確信度・判定には使わない。

4. **反証可能な一文に整形する** — 「私は〈状況・制約〉のもとで〈誰／何〉のために〈こういう目的〉を果たしたい」の形式で、何が起きれば揺らぐ／立ち上がるかが明確な一文にする。検証不能な言い切り（「〜が大事だと思う」）は、何を試せば確かめられるかを問い返して書き換える。

5. **初期確信度・ステータスを決める** — P にサブタイプは無い。証拠がまだ壁打ちだけなら確信度 1-2、探索を始めていれば `status: 探索中`。**外界の証拠がまだ無い段階では確信度を 3 以上に上げない**（証拠の非対称性。上げるのは `/learning`）。核心の目的なら frontmatter `core: true`。

6. **レコードを発番・作成し、接地する** — `wiki/purposes/` の既存最大+1で `P-NNN` を採番（再利用禁止）。`templates/purpose.md` に従って作成。`id` はファイル名と同じ接頭辞つき。`short-title` を書く。
   - **接地（grounded-in・①）**: 手順2で数えた手中の鳥に根ざすなら frontmatter `grounded-in` に対応する制約 `[[C-NNN]]` を配列で列挙し、本文「系譜・接地」にも wikilink を併記する（二重表現）。確信度が高い（5以上）のに未接地の P は hwlint が `grounding-gap` で警告する。
   - **系譜**: 種が別の P から派生・ピボットしたなら `derived-from`（単一）、因果的に導くなら `leads-to`、を frontmatter＋本文 wikilink の二重表現で書く。
   - 確信度履歴テーブルに初期行を入れる。`.gitkeep` が残っていれば削除してよい。

7. **index と log を更新する** — `wiki/index.md` の目的仮説表・制約表に行を追加。`wiki/log.md` に追記:
   `## [YYYY-MM-DD] purpose | P-NNN <要約> → 精錬・確信度N/ステータス`（C を起こしたら `constraint | C-NNN … → 起票（接地: P-NNN）` も追記）

## 目的仮説の取り下げ・書き換え（revises）

- **取り下げ**（試行に未紐づけの撤回。反証ではない）: 対象 `wiki/purposes/P-NNN.md` を削除し、`wiki/log.md` に `取り下げ（ユーザー判断）… ID P-NNN は欠番として再利用しない` を追記。ID は欠番として残す。被リンク `[[P-NNN]]` を grep して繋ぎ直す。`index.md` の行を削除。
- **書き換え**（前言撤回して新しい目的に立て直す）: 新しい `P-MMM` を起票し、frontmatter `revises: P-NNN`（＋本文 wikilink）で旧目的を指す。旧 P は `status: 棚上げ` にして残す（歴史性）。壁打ちでの書き換えは自由（確信度を上げるのでなく、目的文を磨く操作）。

## 守ること

- 一度に複数を量産しない。1本ずつ丁寧に。反証条件を言えない文は仮説ではない。
- 制約は「制限」でなく「出発点」。抽象的な自己PRにせず、いま実際に使える具体的な資源として書く。
- **壁打ちだけで確信度を上げない**。精錬（言語化の解像度を上げる）・接地は確信の根拠にならない。確信を育てるのは `/planning`→`/learning`（外界の証拠）。
