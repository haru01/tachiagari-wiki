# /learning — 生データの取り込みと学び(LEARN)作成・確信度更新（ReAct の Observe）

日々の生データ（壁打ち／試行／第三者反応）を取り込み、**学びレコード LEARN を新規作成**して事実・解釈・驚きを結晶させる。**外界に触れた証拠（試行・第三者反応）のときだけ**、確信度の更新を**提案 → ユーザー承認 → 反映**する。学びは常に新規 LEARN として積む（update より create）。

> **共通規約**（案件解決・ID/接頭辞・リンク記法と `../` 深さ・.gitkeep・承認規律）は [CLAUDE.md「スキル共通規約」](../../../CLAUDE.md) が正典。以下は本スキル固有の手順。

## 手順

1. **生データを sources/ に置き、種別を判定する** — まだ置かれていなければ `sources/` に保存する。**冒頭に種別タグを必ず書く**（`> **種別**: trial | dialogue | third-party`）。sources/ は読むだけ・以後編集しない。
   - `trial` = 現実の試行の記録（やってみた・打診した・断られた）
   - `third-party` = 第三者の生の反応（面談メモ・フィードバック）
   - `dialogue` = 壁打ち・質問セッション（エージェントとの対話）

2. **種別で分岐し、学び LEARN を新規作成する** — どちらの場合も学び LEARN を1本立てる（旧・内省 REF はこの LEARN に統合された）。`wiki/learnings/` の既存最大+1で `LEARN-NNN` を採番し `templates/learning.md` で作成する。`id` はファイル名と同じ接頭辞つき。本文に: 学びの要点（一行・board へ射影）／事実（observed・原文引用中心）／解釈（inference・事実と分ける）／驚き・想定外（無ければ正直に「なし」＝停滞のシグナル）。

   ### 2a. dialogue（壁打ち）の場合 — 回顧型 LEARN・確信度は上げない
   - `type: self-reflection`、**`learns-from` は持たない**（回顧型）。本文冒頭は「学習元: なし（回顧型）」。
   - **確信度を上げてはならない**（外界に触れていない）。壁打ちで目的文の解像度が上がった／前言撤回が要るなら、`/formulating` の `revises` で**目的文を磨く**（＝言語化の改善であって確信の根拠ではない）。
   - 確信度を**下げる**方向（自分でおかしいと気づいた）は許される。その場合は下げの根拠（`〈壁打ち〉再考して引き下げ`）を書き、対象 P の確信度履歴に この LEARN `[[LEARN-NNN]]` を紐づけて追記してよい。

   ### 2b. trial / third-party（外界に触れた）の場合 — 計画型 LEARN を ACT に紐づけて確信度を提案
   - **対応する試行 ACT（行動計画）を特定/作成する**。`/planning` で事前に立てた ACT があればそれを使う（テストカードは編集しない）。無ければ `wiki/activities/` の既存最大+1で `ACT-NNN` を採番し `templates/activity.md` で作成（`type`: 打診/やってみる/面談/観察。`purposes` に対象 `[[P-NNN]]`・`riskiest-assumption`。事後補完でも成功基準は当時の意図として正直に書く）。
   - LEARN の frontmatter に `type`（活動種別）・`learns-from: [[ACT-NNN]]`（**本文にも wikilink**）・`date` を書き、生データパス（冒頭に種別タグ）を記す。
   - **成功基準を〈支持／反証／判断保留／是正〉で判定**し、LEARN frontmatter `outcome` に永続化する。

3. **確信度・ステータスの更新を提案する（2b のとき）** — 対象 P ごとに「現在値 → 提案値・提案ステータス・理由」を提示する。根拠列の先頭に証拠種別タグ（trial→`〈試行〉` または繰り返しなら `〈継続〉`、third-party→`〈他者反応〉`）。**必ずユーザーの承認を得てから反映する**。
   - 成功基準が未達（反証・判断保留）なら原則として確信度を上げない（据え置き／下げる）。弱いシグナルで上げる場合は理由を判定と切り離して明記する（部分証拠・架空データで水増ししない）。
   - 承認要否の段階化（非対話/バッチ）は共通規約5に従う。

4. **承認後に反映する** — 対象目的 `wiki/purposes/P-NNN.md` の frontmatter `confidence`/`status` を更新し、確信度履歴テーブルに1行追記する（活動列に**この学び `[[LEARN-NNN]]`**、根拠列の先頭に証拠種別タグ）。LEARN の確信度更新テーブルも埋める。
   - **確信度を上げる行は、根拠タグが〈試行〉以上でなければならない**（hwlint `check_evidence_asymmetry` が壁打ち単体の上昇を error で弾く）。

5. **レモネード（④想定外を逆手に取る）** — 学びの「驚き・想定外」「断られ・反証」「偶然（狙っていなかった反応・引き合い）」を棚卸しし、逆手に取れる素材を並べる。各素材について「この想定外は、どんな別の目的・別の相手・別の切り口を示唆しているか」を問い、**新しい方向の入口**として読み替える。溜まっていたら手渡す:
   - **新しい目的の種** → `/surfacing`（confidence 1-2・未検証で起票。既存 P と別系統なら本文に、派生なら `derived-from`、対立軸なら `counters`）。**事後発見は事前登録した検証でないので確信度を上げすぎない**。
   - **ピボット** → `/deciding`（`type: ピボット`。新目的の `derived-from` に旧 P、前言撤回して立て直すなら `/formulating` の `revises`）。
   - 手渡したら `wiki/explore-log.md` に `探索再起動 | <想定外> を逆手に → …` を1行追記する。

6. **index と log を更新する** — `wiki/index.md` の該当行を更新。`wiki/log.md` に追記:
   - 回顧型（dialogue）: `## [YYYY-MM-DD] self-reflection | LEARN-NNN <要約> → P-NNN 内省（確信度は据え置き）`
   - 確信度更新あり: `## [YYYY-MM-DD] <ACTのtype> | LEARN-NNN <要約> → P-NNN 確信度X→Y/ステータス`（証拠の試行 ACT は LEARN の `learns-from` から辿れる）
   - レモネードで種化/ピボットしたら `lemonade | <想定外> を逆手に → P-NNN 新規/ピボット` も追記。

## 守ること

- 事実と解釈を必ず分ける。「相手が言ったこと」と「自分がそう思うこと」は別物。
- 学びは**常に新規 LEARN として積む**。ACT のテストカード（成功基準・riskiest-assumption）は後から書き換えない（後知恵バイアス防止・不変ルール7）。
- **確信度を上げてよいのは trial / third-party のときだけ**（証拠の非対称性）。壁打ち沼を防ぐ核心。お世辞・共感・「いいね」は〈壁打ち〉相当で上げない（[playbooks/interviewing.md](../../../playbooks/interviewing.md)）。
- 架空/脳内シミュレーションデータは冒頭に「架空・実証拠として扱わない」と明記（確信度は上限8）。
