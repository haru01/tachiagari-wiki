# /planning — 次の試行を許容損失内で設計する（②許容可能な損失・③クレイジーキルト）

「確信度が低く・重要（core／未接地／偽の収束の疑い）・未検証/探索中」の目的仮説を選び、**外界にぶつける最小の試行（ACT）**を設計する。エフェクチュエーション②許容可能な損失（期待収益でなく失ってよい範囲で踏み出す）と③クレイジーキルト（乗ってくれるパートナーに事前コミットを求める）をこの設計手順に織り込む。**確信度は動かさない**（設計であって観測でない。確信度更新は実施後の `/learning`）。

> **共通規約**（案件解決・ID/接頭辞・リンク記法と `../` 深さ・.gitkeep・承認規律）は [CLAUDE.md「スキル共通規約」](../../../CLAUDE.md)、エフェクチュエーション理論は [playbooks/effectuation.md](../../../playbooks/effectuation.md) が正典。以下は本スキル固有の手順。

## 手順

1. **現在案件を読む**（→ 共通規約1）。`wiki/index.md`（全目的仮説）と `wiki/purposes/`、既存の試行 ACT・手中の鳥 C を把握する。

2. **次に検証すべき目的を選ぶ** — 「確信度が低い × 重要（`core`／未接地／`untested-focus`＝高確信なのに検証ゼロ）× 未検証/探索中」の目的を優先候補として提示し、`AskUserQuestion` でどれを試すか選んでもらう。一度に検証しすぎない（最重要の1-2本に絞る）。

3. **予測的思考を診断する（②）** — 対象の計画・言い分に次の兆候がないか引用つきで突く:
   - 「うまくいけば大きい」（期待収益で正当化）／「もっと確証を得てから」「完璧に準備してから」（予測に逃げている）／一発勝負・後戻りできない賭け方。
   - 効果的思考では**下振れ（失う量）**を先に見る。

4. **許容損失を確定する（②）** — `AskUserQuestion` で1問ずつ、次の試行で「**結果に関わらず失ってよい量**」を洗い出す: 時間（何時間／何日まで）／お金（いくらまで）／評判・関係（誰にどう思われても構わない範囲）／機会（この間できない他のこと）。「失ったら痛いが致命的でない」線を引く。ここを超える賭けは却下・分割する。

5. **パートナーと事前コミットを設計する（③・打診のとき）** — 目的を自分だけで完結させようとしていないか（「まず完成させてから見せる」）を突く。乗ってくれそうな人・場を、既存 C（`type: 誰を知っているか`。例 [[SELF-C-004]]）を起点に洗い出す（新しいつながりは C として起票してよい）。各候補に「**いま求められる最小のコミット**」——時間・紹介・小さな約束・次に会う約束——を設計する。お世辞・「いいね」はコミットでない（[playbooks/interviewing.md](../../../playbooks/interviewing.md)）。**相手がコストを払う**約束を成功基準にする。

6. **許容損失内の最小の試行 ACT を起票する** — 選んだ検証の**最小の一歩**を、許容損失に収まる形で設計する（承認を得てから作成）。`wiki/activities/` の既存最大+1で `ACT-NNN` を採番し `templates/activity.md`（テストカードのみのレコード）で作成する:
   - `type` は 打診／やってみる／面談／観察。`id` はファイル名と同じ接頭辞つき。`purposes` に対象 P（接頭辞つき配列・本文にも `[[P-NNN]]`）。
   - **frontmatter `riskiest-assumption`** に「この試行で崩れたら目的が崩れる一点」を一文で必ず記入する（検証前に確定・後から書き換えない）。
   - 本文の行動計画（テストカード）に 目的／方法／指標／**成功基準**／**許容損失（今回失ってよい量）** を書く。打診なら成功基準＝相手が具体的なコミット（コストを払う約束）をするか。**成功基準は検証開始後に書き換えない**（後知恵バイアス防止・不変ルール7）。
   - **ACT には結果・学びを書かない**——実施後に `/learning` が学び LEARN を `learns-from` で紐づけて起こす。`.gitkeep` が残っていれば削除してよい。
   - コミット規模そのものの判断（大きく賭けるか）なら、ACT でなく `/deciding`（DEC 本文に許容損失を刻む）へ引き渡す。

7. **log を更新する** — `wiki/log.md` に追記:
   `## [YYYY-MM-DD] <ACTのtype> | ACT-NNN <要約>（許容損失: …）→ 試行設計（未実施）`

## 守ること

- 期待収益（上振れ）で GO を出さない。**下振れ（失ってよい量）**で GO/分割/却下を決める。「もっと考えてから」を許容損失内の行動に変える。
- 競合分析に時間を使うより、乗ってくれる人を1人見つけて小さくコミットしてもらう。コミットは相手がコストを払う約束に限る（お世辞・関心表明は〈壁打ち〉相当）。
- **このスキルは確信度・ステータスを動かさない**（試行の設計まで）。実施結果の取り込みと確信度更新は `/learning`。得たコミットは第三者反応（third-party）証拠として `/learning` が反映する。
- 成功基準・`riskiest-assumption` は検証前に確定する。確証バイアスに抗い、支持例だけを集める設計にしない（[playbooks/interviewing.md](../../../playbooks/interviewing.md)）。
