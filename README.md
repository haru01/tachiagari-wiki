# tachiagari-wiki — キャリア目的形成Wiki

試行錯誤のループを通じて、**キャリアの目的・制約・使命が本人の中に事後的に立ち上がること**を支援する個人向け LLM-wiki。日々の壁打ち・試行を沈殿させて**確信を育て**、停滞したら**意図的に確信を揺らして探索域を開き直す**。目的が立ち上がったら目的達成型エージェントへ接続する。

`haru01/hypothesis-wiki`（スタートアップの仮説検証 CPF→PMF）を写像元に、キャリア目的形成ドメインへフォークしたもの。

## コアの考え方

- **目的は事前に設定や見つけるものではなく、試行錯誤で事後的に立ち上がる。** 最初の確信度は低くてよい。
- **二つの温度**: 確信度（目的の硬さ）と当事者性温度（関わりの深さ）は別軸（当事者性はフェーズ1では未実装・予約のみ）。
- **証拠の非対称性**: 確信度を上げてよいのは**外界に触れた証拠**（〈試行〉〈他者反応〉〈継続〉）に紐づくときだけ。壁打ち（エージェントとの対話）単体では上げない（壁打ち沼の防止）。
- **Effectuation（効果的思考の5原則）**: 予測でなく行動で未来を作る。①手中の鳥（手の内の資源＝制約Cから始める）／②許容可能な損失／③クレイジーキルト（パートナーの事前コミット）／④レモネード（想定外を逆手に）／⑤飛行機のパイロット（行動で制御）。理論は [playbooks/effectuation.md](playbooks/effectuation.md)。

## レコード種別（型）

`P` 目的仮説 ／ `C` 制約・手中の鳥 ／ `ACT` 試行（行動計画） ／ `LEARN` 学習（計画型＝実施後の学び／回顧型＝壁打ち内省・ゆさぶり反証監査） ／ `DEC` 意思決定。仮説検証（P→ACT→LEARN→DEC）を基本軸に回す。型・関係・状態機械の正本は [ontology.yaml](ontology.yaml)（人間可読は [ontology.md](ontology.md)）。

## 使い方（フェーズ1・手動ループ）

操作は **Claude Code のスキル**（スラッシュコマンド）で行う。チャットに `/surfacing` のように打つと、Claude が「規律あるWikiの保守者」として問いを立て、規約に従って `projects/<slug>/wiki/` にレコードを起票・更新する。Claude は触媒・鏡であって、目的を代わりに決めない。エフェクチュエーションの5原則は独立スキルにせず、仮説検証の骨格スキルの手順に溶かしている。

### はじめの一歩（初回）

1. **器を用意する — `/new-person`**
   自分用の案件（`projects/<slug>/`）を雛形から作る。まず試すだけなら、同梱の `self` 案件をそのまま使ってもよい。
2. **種を出す — `/surfacing`**
   Claude が「時間を忘れて没頭したこと」などを1問ずつ聞き、答えから**目的仮説（P）の種**を低い確信度（1〜2）で起票する。ここで確信を高めようとしなくてよい。
3. **反証可能にして接地する — `/formulating`**
   種を「何が起きたら“やっぱり違った”と分かるか」（反証条件）まで1問ずつ精錬し、検証できる一文にする。あわせて**①手中の鳥**（自分は誰か／何を知っているか／誰を知っているか）を制約 C として数え、目的に `grounded-in` で接地する。

### 確信を育てるループ（2回目以降）

種ができたら、以下を回して**外界に触れながら確信を育てる**。仮説検証（P→ACT→LEARN→DEC）が基本軸で、エフェクチュエーション5原則はその手順に溶けている（理論: [playbooks/effectuation.md](playbooks/effectuation.md)）。

1. **試行を設計する — `/planning`（②許容損失＋③クレイジーキルト）**
   次に検証すべき目的を選び、「結果に関わらず失ってよい範囲（許容可能な損失）」で最小の試行（ACT）を設計する。乗ってくれるパートナーに事前コミットを取りにいく打診もここで組む。
2. **実際に試す（人が動く）**
   設計した試行を現実世界でやってみる。ここが確信の源泉。
3. **学びを立てて取り込む — `/learning`（Observe＋④レモネード）**
   壁打ち・試行・第三者反応の生データを取り込み、学び（LEARN）を立てる。**確信度を上げられるのは外界に触れた証拠（trial／third-party）のときだけ**。壁打ち（dialogue）だけでは上げない（→ 壁打ち沼の防止＝証拠の非対称性）。想定外・驚き・断られは末尾のレモネード手順で新しい種（`/surfacing`）やピボット（`/deciding`）へ手渡す。
4. **停滞したら揺らす — `/chabudai`（⑤飛行機のパイロット）**
   「予測・過信への逃避」「根拠なき確信」を突いて確信度を引き下げ、行動へ引き戻す（深さ方向の揺さぶり・反証監査）。露出した不協和から新しい探索域を開く。

```
/formulating（①手中の鳥で接地）→ /planning（②③試行設計）→ 実際に試す → /learning（証拠なら確信度↑・④レモネード）
   ↑                                                                            │
   └──────────────── /surfacing（広げる）・/chabudai（揺らす）←────────────────┘
```

### セッションの例

```
あなた: /surfacing
Claude: （没頭したこと・放っておけないことを1問ずつ質問）
        → SELF-P-001「効くツールで新領域挑戦を支援する」を確信度2で起票

あなた: /formulating
Claude: （反証条件を1問ずつ精錬＋手の内の資源を質問）
        → P-001 を反証可能な一文に。制約 C を4件起票し grounded-in で接地

あなた: /planning
Claude: （許容できる損失を確認）→ 最小の打診 ACT を設計（未実施）

… 現実で打診してみる …

あなた: /learning  （打診結果を sources/ に置いてから）
Claude: 学び LEARN を起票。他者が動いた証拠なので確信度 2→5 を提案 → 承認で反映
```

### スキル一覧（骨格 ＋ 横断）

| 相 | スキル |
|---|---|
| セットアップ | `/new-person` |
| 種出し（幅出し再起動口も兼ねる） | `/surfacing` |
| 精錬＋①手中の鳥で接地 | `/formulating` |
| 試行設計（②許容損失＋③クレイジーキルト） | `/planning` |
| 取り込み・学び作成・確信度更新＋④レモネード | `/learning` |
| 岐路の意思決定 | `/deciding` |
| 揺さぶり・反証監査（⑤飛行機のパイロット） | `/chabudai` |
| 保守 | `/lint` |

俯瞰（系譜・試行ボード・関係グラフ）はスキルではなく `wiki/views/` の機械生成ビュー（Stop フックが自動再生成）。

## ツール

```bash
python3 tools/hwlint.py                # 決定論 lint（証拠非対称ルール含む）
python3 tools/gen_views.py list|board|relations   # ビュー生成
python3 tools/gen_ontology_doc.py      # ontology.yaml → ontology.md 再生成
python3 -m unittest discover -s tests   # テスト
```

Claude Code では Stop フックが自動で lint とビュー再生成を行う。初回に `git config core.hooksPath .githooks`。

## ロードマップ

- **フェーズ1（現在）**: 手動ループ＋日次沈殿。停滞検知は手動。
- **フェーズ2**: `/stall-check` で停滞検知を自動化（当事者性温度を本実装。確信度は自動で下げず本人承認を挟む）。
- **フェーズ3**: `/handoff` で立ち上がった目的を目的達成型エージェントへ接続。
- **フェーズ4**: 多人数運用への一般化。
