# 自力でH/TESTまで到達したが前進の具体は出ず、体験が既存の進め方から遠かった

> **架空・実証拠として扱わない**（公開リポジトリ向けに脚色改変した架空事例。この学びに紐づく確信度は上限8・実観測の代わりに使わない）

学習元の試行: [[SELF-ACT-002]]

生データ: `sources/2026-07-28-third-party-架空-Eさん面談-hypothesis-wiki.md`（種別: third-party・架空）

### 学びの要点

渡した hypothesis-wiki は**伴走なしで H／TEST まで回され、インタビュースクリプトという成果物まで出た**（＝「触られない・詰まって終わる」という最弱の反証は回避された）。しかし [[SELF-P-001]] の成否条件である**相手の前進は起きなかった**。障壁は機能の欠落ではなく、**単独チャットで書き切る体験が、複数人＋デジタル付箋という既存の進め方から遠すぎたこと**にある。

### 事実（observed）

- **面談前に、Eさんが自力で**（面談者の伴走・説明なしに）触っていた。到達点は「会話を試す → プロジェクト作成 → **H・TEST** 作成 → **インタビュースクリプト**作成」まで。
- 摩擦として出た言葉: 「**チャット中心の会話で進める体験は、やっぱり難しい**」。
- 「**まず複数人でデジタル付箋を使って話して、まとまったものを引き渡したい**」— **Eさん側から出た**要望。
- Eさんのチームは**実際に別ツールのデジタル付箋で議論をまとめている**。
- 「**返事を返す前に、AIが先に会話を進めてしまうことがあった**」（ツール側の不具合）。
- **前進の具体は出なかった**。次に誰に聞く・いつ再度使う、といった予定の言明もなかった。
- インタビュースクリプトの出来には好意的反応があった。→ ACT-002 の事前の取り決めにより**指標にカウントしない**。
- Eさんのチームは**自分たちなりに利用シーンを検討し、どこをAIに任せどこを人がやるかの分担を整理していた**。
- 「会話して成果物は出てくるが、**その後どこを見ればいいのか分かりにくい**」という指摘も出た。
- 他の人に見せた／勧めたという話は出なかった（波及はデータなし）。
- レコード数・触った日付の広がり・画面での成果物確認は**していない**（痕跡の確認は自己申告どまり）。
- 許容損失の枠内で終了（約30分1回・面談前の機能追加なし・催促なし）。

### 解釈（inference）

- **反証の一段目は回避された**。ツールは他社の相手が自力で起動でき、成果物が出る水準にはある。[[SELF-ACT-002]] の riskiest-assumption のうち「触られていない／一度触って止まっている」は起きていない。
- しかし同じ riskiest-assumption の後半——「**実際に一歩前に進める**」——は満たされていない。[[SELF-P-001]] の成否条件は「相手の前進」に置いてあるので、**この試行は目的を支持していない**。好意的反応は〈壁打ち〉相当であり、確信の根拠にしない（[playbooks/interviewing.md](../../../../playbooks/interviewing.md)）。
- **障壁の所在が移動した**。問いは「ツールが動くか」から「**既存の進め方に接続できるか**」へ移った。発散（複数人・デジタル付箋）と収束（wiki の構造化記録）の間に**引き渡し口がない**ことが、Eさんの言葉から具体的に指し示されている。
- 「AIが先に会話を進めてしまう」は**ツール側の明確な不具合**であり、上記の体験ギャップとは性質が違う（直せば消える種類の摩擦）。摩擦を habits の問題と決めつける前に、こちらを潰す必要がある。
- **痕跡確認をしなかった**点は、この試行の設計（「自己申告より痕跡」）に対する自分側の実行漏れ。次回の面談設計で締める。
- **n=1・社外1人**。相手差を切り分けられないため、いずれの方向にも強く振らない。

### 驚き・想定外

- Eさんのチームは受け手として道具を評価するのではなく、**自分たちの利用シーンを自前で設計し、AIと人の分担を整理していた**。渡したものが「そのまま使う道具」ではなく「**分担設計の材料**」として読まれていた。
- 望まれたのは機能追加ではなく**引き渡し（インポート）の口**だった。「AIとの対話で本人に書かせる」という設計の中心前提に、外から別の形が提示された。
- 「成果物は出るが次にどこを見ればいいか分からない」——出口（次の一手の提示）が弱いという指摘。

### 次のアクション

- **「AIが先に会話を進める」不具合を潰す**。これは是正で済む話なので、体験ギャップの議論と混ぜない。
- **引き渡し口（発散→収束）を種化するか判断する** → `/surfacing`。「複数人の発散（付箋）で出たものを受け取って構造化する」方向は、「AIとの対話で本人に articulate させる」という現行前提への**対抗仮説（`counters`）候補**。
- **「AIと人の分担の型」自体が支援対象という別方向の種** → `/surfacing`。Eさんのチームが自前でやっていたのはまさにこれで、需要はツールより分担設計の側にあるかもしれない。
- **前進の具体を取り直す試行の設計** → `/planning`。ただし [[SELF-ACT-002]] の許容損失（相手の時間30分1回）は使い切っており、Eさんへの再依頼は**別 ACT として損失を切り直す**。
- 次の面談設計では**痕跡を画面で確認する**手順を落とさない（今回の実行漏れ）。
- [[SELF-ACT-003]]（社内 `/lean-canvas`）の結果と並べて読む。社内・社外の両方で「体験の重さ／進め方との距離」が出るなら、それは相手差ではなく設計の問題。
