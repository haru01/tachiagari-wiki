## 試行1 — 訪問先マネージャ2人にtachiagari-wikiを打診（1on1前の道具として）（2026-07-23・打診） [[SELF-ACT-001]]

- **対象目的**: [[SELF-P-001]]
- **最もリスクの高い前提**: 訪問先マネージャが、tachiagari-wiki を自分のチームの「1on1前にメンバーがキャリアを考え直す道具」として実際に使いたいと思う（2人に打診して1人も乗らなければ、需要前提もメンバー展開も [[SELF-P-001]] も崩れる）
- **検証方法**: 再来週の訪問の場で、マネージャ **2人** に同じデモを見せ（各15〜30分）、次を問う: 「1on1に臨む前に、メンバーに使ってもらう道具として使いたいと思うか」 「どのメンバーに効きそうか」 **リジェクトされたら『何が引っかかったか』を具体的に聞き出す**（断られること自体が学びの入力）。押し売りはせず、断られたら引く。2人の反応が割れた場合は、その差が「相手差」なのか「ツール差（刺さる文脈）」なのかを見分ける材料も拾う。
- **成功基準**: **2人のうち少なくとも1人**が「このメンバーに、この1on1で使ってみたい」と**自分から次の一歩を口にしたら支持**。2人とも「面白いね」止まり・要らないなら**反証**（要因を記録）。1人が乗り1人が断る割れなら**判断保留**とし、両者の要因差を実施後の LEARN に残す。
- **結果（学びの要点）**: 持っていった仮説は「**次世代リーダーを育てたい → 育成の中心は 1on1 → だから 1on1 の前後で使う道具が響く**」という三段の連鎖だった。1人目のマネージャ（Mさん）の反応で外れたのは**3段目**である。育成というテーマは当たっていたが、Mさんは「**1on1 は1対1なのでこの課題は扱いきれない。別の場を作ってそこでやるほうがいい**」と返した。**外れたのは道具ではなく、こちらが置いた「1on1の前後」という置き場所**。ただし「使ってみたい」の判断・次の一歩は出ておらず、しかも**見せたのは README の説明文のみ**で道具への反応としては読めない——**打診の刺激が弱すぎた**ことも同時に判明した。（学び [[SELF-LEARN-002]]）

- **最もリスクの高い前提**: 渡された hypothesis-wiki を、社外の相手が自分の現場の仮説検証に対して自力で使い、実際に一歩前に進める（触られていない／一度触って止まっているなら、「効くツールを作れば相手の挑戦が前に進む」という [[SELF-P-001]] の中核前提が崩れる）
- **検証方法**: 相手に **15〜30分**（1回）もらい、次の順で聴く。順序を守る——先に感想を聴くと、使っていない場合でも社交的な評価で埋まってしまう。 1. **使用の痕跡を先に確認する**（自己申告より痕跡）: 実際に作ったレコード（H／TEST／LEARN／DEC）や wiki のファイル・コミットを画面で見せてもらう。「どこまで進んだか」を本人の言葉ではなく成果物で確認する。 2. **未使用／途中で止まっていたら、そこを掘る**: どこで手が止まったか（セットアップ／規約の理解／自分の案件に当てはめる段）。「使わなかった理由」を具体的に聞き出す（それがこの試行の主産物になりうる）。 3. **使っていたら、前進の具体を1つ挙げてもらう**: これを使ったことで、自分の仮説検証で**何が変わったか**（判断が変わった／次の検証が決まった／過去の学びを引き出せた）。抽象的な評価しか出ないなら、それは前進なしとして記録する。 4. **次の一歩を自分から口にするか観察する**（誘導しない）: 次に何に使うつもりか。こちらが提案する前に相手が口にするかどうかを見る。 5. **押し売りしない**。使っていないなら催促・リマインドはせず、要因だけもらって引く。 **「いいですね」「面白い」は指標にカウントしない**（偽の確証の典型。hypothesis-wiki 自身が抗おうとしている失敗パターンでもある）。
- **成功基準**: **開始後は書き換えない**（後知恵バイアス防止・不変ルール7）。 **支持**: 相手が**自分の案件でレコードを作っており（痕跡あり）**、かつ「これで自分の検証/判断がこう前に進んだ」という**具体を1つ以上**挙げられる。 **反証**: 触っていない、または一度触って止まっており、その要因が「自分の課題に合わない／必要でない」。 **判断保留**: 使ってはいるが、(a) 自分の伴走・説明があって初めて進んだ（自力でない）、または (b) レコードはあるが前進の具体を挙げられない（「面白い」止まり）。 **是正**: 止まった要因がツール側の明確な欠陥（セットアップで詰まった等）で、目的仮説そのものは崩れていない場合。 注: **n=1**。支持が出ても相手差を切り分けられないため、実施後の LEARN での確信度引き上げ提案は控えめに（強い引き上げは相手を増やす次の ACT を要する）。
- **結果（学びの要点）**: 渡した hypothesis-wiki は**伴走なしで H／TEST まで回され、インタビュースクリプトという成果物まで出た**（＝「触られない・詰まって終わる」という最弱の反証は回避された）。しかし [[SELF-P-001]] の成否条件である**相手の前進は起きなかった**。障壁は機能の欠落ではなく、**単独チャットで書き切る体験が、複数人＋デジタル付箋という既存の進め方から遠すぎたこと**にある。（学び [[SELF-LEARN-001]]）
